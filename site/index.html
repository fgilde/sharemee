What Shareme is built to do

The target is everything a mature digital asset management system does, plus a document store, a wiki and an intranet that share the same permissions, metadata and search.

Assets

Versions and renditions

Chunked uploads, file versions, thumbnails, previews and print renditions, watermarks, crops, video and 3D previews — every file shown with MudExFileDisplay.

Metadata

Your own data model

Define entity types, relations and fields with lists, languages and contexts. Property sets with required fields, inheritance from folders, mass edit, import and export.

Permissions

Down to a single file

Roles, groups and fine-grained permissions, granted and revoked on any folder or asset, inherited downwards and interruptible where you need it.

Audit

Every change, field by field

Who changed what, from which value to which, for every entity — with restorable versions for pages, templates and settings.

Collaboration

Workspaces and sharing

Kanban workspaces with states and tasks, comments with mentions, watchers, notifications, and expiring external shares.

Knowledge & intranet

Pages, news, people

Versioned wiki pages with diffs, news, a personal start page with widgets and a people directory — searchable together with every asset.

Realtime

Live everywhere

Any change reaches every open browser through one generic SignalR channel — lists, details, jobs and notifications update without a reload.

API & AI

REST, Swagger and MCP

Everything is an API first, documented with OpenAPI. A built-in MCP endpoint and a configurable assistant act strictly within the calling user's permissions.

Architecture

A modular .NET 10 application orchestrated by Aspire, built on Coworkee — a small framework of NuGet packages for modules, permissions, settings, mail templates, audit and realtime.

ServiceRole
shareme-webBlazor Web App with MudBlazor, acts as the backend for the browser
shareme-authOpenID Connect server for users, tenants and external logins
shareme-apiREST, SignalR hub and MCP endpoint
shareme-processingBackground jobs for renditions, metadata extraction and imports
Postgres · Redis · ElasticsearchData, cache and realtime backplane, search

Get started

You need the .NET 10 SDK and Docker. Until the Coworkee packages are on NuGet, the Coworkee repository sits next to Shareme in a folder called coworkee.

git clone https://github.com/fgilde/shareme.git
pwsh coworkee/build/pack-local.ps1
dotnet run --project shareme/src/Shareme.AppHost

The Aspire dashboard opens and starts Postgres, Redis, Mailpit, the migrations and the API.
