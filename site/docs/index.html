Status & roadmap

Shareme is in early development. The foundation is done: the Coworkee core packages and a Shareme Aspire application with database, migrations and an API. Features follow in phases.

PhaseScope
P0Foundation: modules, dispatcher, audit, outbox, auth server, users, roles, permissions, settings, mail templates, themes, realtime, setup wizard
P1Graph, metadata and assets: folders, custom types, uploads, versions, renditions, file display, per-item permissions
P2Search with facets, saved searches, reindex
P3Full rendition pipeline: video, office, PDF, 3D, watermarks, crop, archives, zip downloads
P4Collaboration: workspaces, states, tasks, comments, shares, notifications
P5Automation: rules, mass edit, import and export, AI tagging
P6Licensing and rights management
P7Knowledge base and intranet
P8AI assistant and MCP tools
P9Data migration and public packages

Requirements

  • .NET SDK 10.0.300 or later (pinned in global.json)
  • Docker, for the Aspire containers and the integration tests
  • The Coworkee repository checked out next to Shareme as ../coworkee, until its packages are published

Quick start

pwsh ../coworkee/build/pack-local.ps1
dotnet run --project src/Shareme.AppHost

The script packs Coworkee into ../coworkee/artifacts/nuget, a local feed that nuget.config already knows. The AppHost starts Postgres, Redis, Mailpit, runs the migrations once and then starts the API. Swagger is at /swagger on the API.

Package or project references

Projects declare what they need with <CoworkeePackage Include="Coworkee.Application" />. By default these become NuGet package references to the local feed. To debug into Coworkee or change it without repacking, switch to project references:

dotnet build -p:CoworkeeReferenceMode=Project

Modules

Every library and every feature is a module. A module registers its services and names the modules it depends on; the loader orders them so dependencies run first and detects cycles.

[DependsOn(typeof(CoworkeeApplicationModule))]
public sealed class ShareMeApplicationModule : CoworkeeModule
{
    public override void ConfigureServices(ModuleServiceContext context) =>
        context.Services.AddMessagingFromAssembly(typeof(ShareMeApplicationModule).Assembly);
}

A web host registers one root module with builder.AddCoworkee<TRoot>() and calls app.UseCoworkee(). Modules that map endpoints implement IWebModule.

Commands and queries

Use cases are requests handled by exactly one handler. The dispatcher runs a fixed middleware pipeline around every request: logging, then validation, then the unit of work, which saves changes only for successful commands. Authorization takes its reserved slot in the pipeline with phase P0.

public sealed record GetSystemInfo : IQuery<Result<SystemInfo>>;

internal sealed class GetSystemInfoHandler : IHandler<GetSystemInfo, Result<SystemInfo>>
{
    public Task<Result<SystemInfo>> HandleAsync(GetSystemInfo request, CancellationToken ct) =>
        Task.FromResult<Result<SystemInfo>>(new SystemInfo("Shareme", "0.1.0"));
}

FluentValidation validators in the same assembly are picked up automatically. A failed validation returns a validation error instead of calling the handler.

Persistence conventions

Derive the database context from CoworkeeDbContext and register it with AddCoworkeeDbContext<T>(). Marker interfaces on entities switch on behaviour:

MarkerEffect
IAuditableCreated and modified time and user are set on save
ISoftDeleteDelete becomes a flag; deleted rows are hidden from queries
IMultiTenantTenant is set from the current user; other tenants' rows are invisible and cannot be written
IHasConcurrencyTokenOptimistic concurrency; conflicts surface as HTTP 409

Every insert, update and delete writes an audit entry with old and new values per field, including changes inside JSON-mapped owned objects. Mark properties with [Sensitive] to mask values or with [NotAudited] to leave them out.

Domain events and outbox

Aggregates raise domain events. On save they are written to an outbox table in the same transaction. A background processor delivers them to IDomainEventHandler<T> implementations, as the user and tenant that raised them, retries failures with exponential backoff and gives up after five attempts. Handlers should be idempotent: delivery is at least once.

HTTP results

group.MapGet("/info", (IDispatcher dispatcher, CancellationToken ct) =>
    dispatcher.SendAsync(new GetSystemInfo(), ct).ToHttpResult());

Successful results return 200 or 204. Errors become problem details: validation 400, forbidden 403, not found 404, conflict 409, anything else 500. Each problem carries the error code.

Testing

dotnet test --solution Shareme.slnx

Tests use xUnit v3 on Microsoft.Testing.Platform. Integration tests run against a real Postgres in a container and reset it between tests. The AppHost smoke test starts the whole Aspire application and calls the API.
