# P4b States und Tasks – Plan

Spec: `docs/superpowers/specs/2026-10-02-p4-collaboration-design.md` Abschnitt 2 (P4b).

- Tasks sind Graph-Knoten (`WorkTask`, Diskriminator `task`) direkt unter ihrem Workspace: Titel = Knotenname, Beschreibung, Fälligkeit, State, Zuständige (Mitglieder mit direktem Grant), Reihenfolge in der Spalte (Sort-Index), Erledigt-Zeitpunkt. Rechte, Audit, Realtime (`children:{workspace}`), Metadaten und Papierkorb kommen vom Graph; Tasks lassen sich nicht verschieben und nehmen keine Kinder; sie zählen nicht als Workspace-Items und bleiben beim Finalisieren im Workspace.
- States (`WorkflowState`) je Workspace: Name, Reihenfolge, genau ein Default, Erledigt-Flag, „nur Owner“, erlaubte Ziel-States (leer = alle). Neue Workspaces bekommen „To do“, „In progress“, „Done“, Templates geben ihre States samt Übergängen weiter; die Migration ergänzt die Standard-States bestehender Workspaces. Löschen eines States verschiebt seine Tasks in den Default.
- Move: Transition und „nur Owner“ geprüft, Version des Tasks muss stimmen (sonst 409), die Spalte wird mit dem Task an der Zielposition neu nummeriert; Domain-Events `TaskMoved`/`TaskAssigned` für P4c.
- Verknüpfte Assets je Task über Edge `link` (nur lesbare Assets).
- UI: Tab „Board“ in Collaboration-Workspaces (MudDropContainer, Spalten je State, nur erlaubte Drops, Fälligkeit rot wenn überfällig, Avatare der Zuständigen, Editor für Titel/Beschreibung/Fälligkeit/Zuständige, Realtime).
- Offen für später: globales Workspace-Board über Workspace-States, State-Verwaltung in der UI (die API ist da).
